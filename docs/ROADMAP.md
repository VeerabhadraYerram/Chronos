# Implementation roadmap

[Repository overview](../README.md) · [Evaluation guide](EVALUATION.md)

This page records scope, not delivery dates or a promise of competition placement.

The [company reference workspace](DELHIVERY_REFERENCE.md) is now the main product: interactive evidence trails, Groq / Gemini / OpenRouter investigations, large connected synthetic operational dataset, temporal client commitments, session graph copies and before/after previews. Public facts and synthetic private records are explicitly distinguished.

## Implemented main product

- Question-specific evidence maps and readable trails with clickable records, relationship provenance and contextual follow-up.
- Source-backed accepted rules with effective and recorded intervals, document-claim comparisons and relevant alerts.
- Generic schema discovery and bounded aggregations, including client counts and numeric invoice queries.
- A connected 9,991-business-entity logistics fixture across 12 clients and multiple operational/finance situations, plus a trusted local data-pack importer tested with an unrelated company.
- Isolated visitor graphs, saved investigations, stale-context handling, scoped graph-copy comparisons and human review drafts.
- Separate database inspection with complete paginated records, relationships, observed schema/indexes, structural checks and JSON export.
- Free Render deployment with a clean prebuilt reference, bounded public API, provider fallbacks and health probes independent of long workspace scans.
- [Actual Cypher documentation](GRAPH_QUERIES.md), [81-test integration milestone and live verification](VALIDATION.md), [submission artifact map](SUBMISSION.md).

## Preserved payments capabilities

- Real FalkorDB knowledge/state storage and graph-copy rehearsal.
- Parameterized accepted-fact selection across partner and two timestamps.
- Deterministic assessment, scoped runbook conflict, and missing-evidence handling.
- Optional Gemini tool loop with response-shape and source-ID validation.
- Source inspection, temporal views, graph expansion, saved receipts, and stale-action rejection.
- Downloadable repair drafts and idempotent in-app approval.
- Synthetic migration/proposal/withdrawal replay and disposable-graph integration checks.

## Next product priorities

| Priority | Work | Acceptance evidence |
| --- | --- | --- |
| 1 | Source-document ingestion beyond trusted JSON packs | A reviewer supplies a new document/export; reviewed extracted facts retain provenance and change a supported investigation without editing fixture code. |
| 2 | Evidence-backed expertise discovery | Reviewer suggestions cite relevant contributions and ownership; they do not equate centrality with competence. |
| 3 | Incremental updates | A new source version updates affected facts, exposes scoped disagreement, and invalidates dependent results with clear history. |
| 4 | Broader evaluation | Varied fixtures, ambiguous identities, missing evidence, and agent explanations are evaluated with recorded failure cases. |
| 5 | Submission media and release checks | Upload and verify the mandatory working demo video, link it from the README/checklist, and complete the organizer form; recheck the existing live deployment before submitting. |

## Later extensions

Live app connectors, versioned ownership/topology, source permissions, explicit publishing approval, transactional ingestion, cross-process coordination, MCP packaging, and multiple cooperating agents. Each needs its own working demonstration and failure handling before it is listed as a capability.
