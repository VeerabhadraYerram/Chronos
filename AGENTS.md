- Check a change through real FalkorDB integration tests and the frontend build. Use uniquely named disposable test graphs; do not reset the user's demo graph during tests.
- Describe actual capabilities and limitations honestly. Never fake baseline failures, measured latency, external publication, merge blocking, or outage predictions.
- Ask the user when consequential scope or authorization is unclear. Routine implementation choices may follow the accepted master plan.
